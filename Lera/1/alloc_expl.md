# **Объяснение работы программы и принципа измерений**

Цель программы — измерить реальное время выделения динамической памяти в QNX 6 тремя механизмами:

1. **new[] / delete[]** — оператор языка C++
2. **malloc() / free()** — аллокатор стандартной библиотеки C
3. **mmap() / munmap()** — выделение страниц через механизмы виртуальной памяти ядра

Для высокоточной оценки временных интервалов используется функция **ClockCycles()**, возвращающая текущий счётчик тактов процессора (Time Stamp Counter, TSC). Так как TSC увеличивается с частотой процессора, длительность операции измеряется следующим образом:

```
Δcycles = ClockCycles_end – ClockCycles_begin
time_ns = Δcycles × 1e9 / cpu_frequency
```

Частота процессора вычисляется экспериментально: программа вызывает ClockCycles(), затем выполняет задержку `delay()` фиксированной длительности (например, 50 мс) и сравнивает значения TSC до и после задержки. Это гарантирует правильное определение частоты даже в тех случаях, когда данные в syspage недостоверны.

Для каждого вида выделения памяти выполняется большое число итераций (100 000), чтобы минимизировать случайные флуктуации и получить статистически устойчивое среднее значение.

Привязка процесса к одному CPU выполняется командой:

```
on -C 0 ./alloc_bench 100000
```

Это устраняет миграции потока между ядрами, что делает измерения воспроизводимыми.

# **Анализ полученных результатов**

Программа напечатала:

```
=== RESULTS (avg cycles) ===
new[]      : 719.196 cycles
malloc()   : 861.947 cycles
mmap()     : 27347.4 cycles

=== RESULTS (ns) ===
new[]      : 258.112 ns
malloc()   : 309.344 ns
mmap()     : 9814.69 ns
```

### 1. **Оператор new[] (≈ 258 ns)**

Выделение небольшой области памяти на куче, использующее быстрый аллокатор.
Время соответствует типичному диапазону 0.2–0.4 мкс для систем с частотой около 3 GHz.

### 2. **malloc() (≈ 309 ns)**

malloc() здесь немного медленнее new[]:

* malloc() может выполнять более сложные проверки и управления фрагментацией
* реализация `libc` для QNX может быть не самой быстрой
* new[] иногда использует оптимизированные быстрые пути

Разница ~20% абсолютно нормальна.

### 3. **mmap() (≈ 9.8 µs)**

mmap создаёт новый участок виртуальной памяти:

* настройка таблиц страниц
* возможные обращения в ядро
* подготовка частично нулевой физической памяти
* переключение в kernel mode → user mode

Такой уровень задержки (5–20 мкс) полностью соответствует ожидаемому.
